## Key Discussion Topics

### Custom Service Plan Pricing Bug (Review Environment)

- **Bug discovered:** When creating/editing a custom service plan for a company, the review view displays the *price difference* (delta from base) instead of the *full adjusted price*
  - Example: Base price is $20, custom set to $30 — review shows "$10" (the difference) instead of "$30"
- **Environment scope:** Bug is present only in the **review environment**. Beta and prod display prices correctly
- **Root cause hypothesis:** Likely introduced by the **CakePHP upgrade**, since beta and prod (pre-upgrade) don't exhibit the behavior
- **Stone's analysis:** Suspects a database ORM mismatch or incorrect table lookup. The custom service plan tables have complex linking that isn't straightforward
- **Inheritance clarification:** Distributors inherit only from base prices; only sub-companies have second-layer inheritance. The bug was reproduced on a distributor (Orases test company), ruling out inheritance as the cause
- **Resolution:** Must be fixed before the CakePHP upgrade rolls to production

### CakePHP Upgrade Testing

- **Laura's Claude testing:** Used Claude with a Chrome extension (in Cowork mode) to crawl pages and identify 500 errors. Found several bugs, but Noah noted some were not related to CakePHP or were not actual bugs
- **Limitation identified:** Automated URL hitting catches broken pages and 500s, but cannot validate functional correctness (e.g., whether data displays correctly)
- **Richard's observation:** Some 500s may be due to inconsistent form handling — some forms use POST, others GET, and direct URL access after POST submissions may naturally fail
- **Aksana's concern:** Some URLs generated by Claude may not be valid routes, just randomly constructed paths
- **Laura to share** the full Claude conversation export with Aksana for review

### Isolated Test Environment Need

- Devs expressed the need for an **isolated environment with the CakePHP upgrade** where they can check out branches and test changes independently
